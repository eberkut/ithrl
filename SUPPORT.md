# Support

Start with the [README](README.md), [native-run guide](docs/native-runs.md), and
[results guide](docs/results.md).

## Choose a report

- **Usage questions or proposed changes:** open a
  [question or proposal](https://github.com/eberkut/ithrl/issues/new?template=proposal.yml).
  Describe what you are trying to do and where the documentation leaves a gap.
- **Reproducible defects:** use the
  [bug report](https://github.com/eberkut/ithrl/issues/new?template=bug.yml).
- **Harness, platform or version incompatibility:** use the
  [compatibility report](https://github.com/eberkut/ithrl/issues/new?template=compatibility.yml).
  Include the harness version and refusal code; a version change alone does not establish
  incompatibility.
- **Suspected vulnerabilities:** follow [SECURITY.md](SECURITY.md) and report privately.
- **Conduct concerns:** use the private contact in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

Search [existing issues](https://github.com/eberkut/ithrl/issues) before opening a report.
Include `ithrl --version`, Python and operating-system versions, the relevant harness version,
sanitized steps, and expected and actual results. A minimal synthetic reproduction is preferable.

Public reports must not contain credentials, private sessions, proprietary source, raw cases,
observation databases or unreviewed diagnostic bundles. Review command output before sharing it;
even paths, prompts and tool arguments can disclose private information.

## Contributions and response times

Discuss changes in an issue before preparing a pull request. Pull requests are limited to
collaborators; see [CONTRIBUTING.md](CONTRIBUTING.md).

Support is provided by the maintainer as time permits. There is no guaranteed response or
resolution time.
