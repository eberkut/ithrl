# An ordinary-session paragraph investigation

An ordinary Codex workflow discussion mixed an administrative upgrade policy with a technical
question: how does the version of an installer action relate to the CLI version selected by its
caller? The observed answer mentioned Databricks. The investigation asked whether that topic would
still appear when the administrative paragraphs were removed, while retaining the technical
question and the other evidence in the selected context.

The smaller context passed fresh preservation confirmation for the fixed topic predicate. It lets
the developer inspect the installer-versus-installed-version distinction in a shorter record.
It establishes neither the answer's correctness nor whether the removed paragraphs influenced the
original answer.

## Source, predicate and intervention

The source was an existing human CLI investigation, selected before fresh observations. It had no
compaction records or images in the materialized history. The native installation was Codex CLI
`0.167.0`; the experiment used a frozen private candidate wheel and the captured model/provider
routing. The raw session, code, paths, routing and identities remain private.

The predicate was fixed before collection: a final response containing `Databricks`, `databricks`
or `DATABRICKS`. This measures topic mention. A quotation, negation or unrelated mention can match;
a semantically relevant paraphrase can fail. It does not grade the correctness, usefulness or
priority of the recommendation.

The selected prior-user field contained eight paragraphs, totaling **1,282 UTF-8 bytes**. The
intervention removed its first four paragraphs: **580 bytes** of action inventory, administrative
approval and pinning-policy discussion. It retained **702 bytes** containing the complete technical
installer/CLI distinction, a separate CLI compatibility question, and clarification questions. The
fixed triggering input and the selected field's remaining text stayed unchanged.

The private edit is described without source or answer excerpts. This description cannot serve as
a replacement prompt or transfer the verdict to a public reproduction.

## What was tested

The experiment first calibrated the immutable original with three observations. Bounded
whole-record reduction removed **34 source context units** while retaining the mixed field. A fine
comparison then tested the frozen paragraph edit relative to that coarse candidate. Search
collected two fresh original and two candidate observations. The **512-byte minimum additional
reduction** was declared separately from the behavioral criterion; the 580-byte edit met it.

After durable selection, fresh confirmation compared the selected **coarse-plus-fine** candidate
with the **full immutable original**. Both arms matched **11/11**. At a 20-percentage-point
preservation margin and nominal 95% one-sided confidence, the result passed the frozen Newcombe
method 10 preservation rule. The reduced allocation was approved before these observations. No
earlier pilot, control or search observations entered the confirmation sample. The
[measurements](../measurements.md#ordinary-session-paragraph-removal) record the exact interval and
the associated Copilot result.

The result supports the topic predicate within the declared margin, assuming independent valid
observations and stationarity. Eleven successes per arm do not prove equal response distributions,
universal preservation or a future minimum match rate. The approximate interval has no uniform
finite-sample coverage guarantee. Search establishes no minimality, necessity, unique cause or
global optimum.

## What the developer can do with the result

The Databricks topic still appeared after removal of the administrative paragraphs. The developer
can inspect the retained technical question and its code/documentation evidence without treating
that discussion as required for this topic check.

Next, trace the installer's version selection and the caller's CLI-version input separately.
Verify the installed version in an isolated, authorized workflow and compare it with the actual
recommendation before changing the workflow. The reduction experiment did not perform this check.

The result does not show that all administrative information disappeared. Equivalent information
may remain elsewhere in history, instructions, code or the fixed triggering input. The source also
carried **29 opaque encrypted reasoning fields**; their contents and influence remain unknown.
Removing a visible paragraph cannot establish that the model lacks its information.

## Execution evidence and cost

The completed workflow used **29 valid observations** and **37 actual and charged provider
requests**, with zero additional possible or pending calls. The **17.334% decrease** in mean
confirmation input tokens includes both whole-record and paragraph removal. It cannot be attributed
to the 580-byte edit alone: no separate coarse-versus-fine token comparison was confirmed. The
[measurement record](../measurements.md#ordinary-session-paragraph-removal) gives the full token,
duration and request counts. Monetary cost and monetary savings are unknown.

A private wire auditor checked every external request and continuation against the source-bound
history, selected edit, fixed trigger and settings under explicit native normalizations. It proves
neither complete historical request equivalence nor provider-internal rendering or reasoning. The
auditor is not part of the shipped runner, and the uncompacted workload does not qualify compaction
on `0.167.0`.

All attempts verified unchanged source/workspace and cleanup; zero actions executed or tool-side
network effects occurred. Active interruption/resume was exercised. Resuming a completed result
added no observations or provider calls, although it republished a summary snapshot. The
[investigation cost record](../measurements.md#investigation-cost-and-unsuccessful-work) includes
earlier controls, failures and incomplete work. Those attempts are not confirmation samples.
Historical accounting remains incomplete; the ledger preserves unknown
usage and observer uncertainty rather than treating them as zero.
